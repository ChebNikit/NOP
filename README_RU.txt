# NOP 1.0 — полный BuildKit R12

Это полный комплект сборки, заменяющий R11 и отдельные патчи R11.2–R11.5. Исходный плеер, панели и функции сохранены. Основной архив содержит исходники, Python NuGet, pip, 34 Windows wheel-пакета, FFmpeg/ffprobe, Deno, libmpv, инструменты 7-Zip, установщики Inno Setup, Visual C++ и Equalizer APO. Для LibreOffice, Inkscape, calibre и Blender включены закреплённые источники и карты файлов. Их оригинальные пакеты передаются в трёх дополнительных архивах кэша; если их не распаковать, сборщик автоматически использует прежние кэши или скачивает пакеты с официальных источников.

**Статус:** настоящая распаковка больших пакетов проверена на Linux. Полная сборка EXE, установка и работа на Windows, включая обязательную LTSC 1809, в этой среде не выполнены. Архив не содержит готового `NOP_Setup.exe` и не является подтверждением его работоспособности. Подробности и результаты — `docs/REPORT_RU.md`.

## Как запустить

1. Распакуйте основной `NOP_BuildKit_R12.zip` **целиком**, в отдельную папку. Прежний R11 можно оставить рядом: его кэш будет найден автоматически. Запускать BAT прямо из окна ZIP нельзя.
   Необязательно: распакуйте `NOP_R12_CACHE_LibreOffice.zip`, `NOP_R12_CACHE_Blender.zip` и `NOP_R12_CACHE_Vector_Ebook.zip` **в ту же папку назначения**, чтобы их содержимое объединилось внутри одного `NOP_BuildKit_Win10_11_R12`. Это исключит скачивание больших SDK. Файлы кода в архивах кэша отсутствуют.
2. Откройте `NOP_BuildKit_Win10_11_R12` и дважды нажмите **`build_windows.bat`**. Глобальные Python, FFmpeg, mpv, Inno Setup и настройка PATH не нужны.
3. Если отсутствует Visual C++ Runtime, Windows запросит согласие на его установку. Это отдельное системное изменение с UAC; отмена запроса остановит сборку с объяснением.
4. Дождитесь строки `CREATED`. Только после успешных проверок результат публикуется в **`release\NOP_Setup.exe`** рядом с BAT. Размер окончательного установщика будет большим, поскольку все движки конвертации включены.

Не требуется удалять Python, wheelhouse или скачанные архивы после ошибки. Повторный запуск использует постоянную рабочую папку **`%LOCALAPPDATA%\NOPBK\R12`** и сохранённые загрузки. Свободное место на её диске — не менее **18 ГиБ**, желательно 25 ГиБ. Основной архив занимает около 467 МБ; весь комплект с тремя необязательными архивами SDK — около 1,6 ГБ. Разделение вызвано ограничением 512 МБ на один передаваемый файл.

Пути с пробелами, кириллицей и скобками передаются как аргументы, без `cmd /c`. Сборка выполняется в более короткой рабочей папке; распаковка ZIP и файловые операции с движками используют расширенные пути Windows. Включать LongPathsEnabled в реестре не нужно.

Если нужно выбрать другой локальный диск, необязательный запуск из CMD:

```bat
set "NOP_BUILD_WORKSPACE=D:\NOPBK\R12"
build_windows.bat
```

Папка должна быть короткой, вне дерева исходников и доступной текущему пользователю. Изменять BAT/Python-файлы не требуется.

## Что изменено после последних ошибок

- **LibreOffice MSI 1603 и прежний 1639:** подготовка движков больше не вызывает `msiexec /a`. Проверенный 7-Zip читает встроенные CAB как данные; таблица файлов именно этой версии MSI восстанавливает имена и каталоги. Установочные действия MSI и системная регистрация движков не запускаются. Код 1603 общий; без журнала MSI нельзя доказать первоначальную причину.
- **Особенности настоящих пакетов:** системные merge-модули VC разных архитектур не смешиваются. 135 шрифтов LibreOffice размещаются в его частном `share/fonts/truetype`. Для 29 внутренних CAB-имён Inkscape с точками в конце учитывается нормализация Windows 7-Zip. Это не имена установленных файлов.
- **BCJ2:** остаётся проверенный нативный 7-Zip 26.05; py7zr не используется для распаковки этого фильтра.
- **429 и повторные загрузки:** все четыре источника конвертеров и свидетельства закреплены локально. Большие архивы включены в три дополнительных пакета кэша; без них применяется автоматическая загрузка или перенос прежнего кэша. При повреждении рабочей копии сборщик сначала восстанавливает её из распакованного полного комплекта по SHA-256, затем при необходимости использует официальный источник и ограниченные повторы.
- **Python / PowerShell:** Python 3.13.17 и его SHA-512 включены; поиск NuGet sidecar для штатной сборки не нужен. PowerShell запускается по абсолютному системному пути. pip использует только закреплённые wheel-файлы; повторная установка локальных пакетов исправляет неполные предыдущие установки.
- **Inno Setup:** оригинальный установщик 7.1.1 включён и закреплён SHA-256. Компилятор подготавливается в рабочей папке для текущего пользователя. Ранняя компиляция сценария проверяет синтаксис интерфейса и Pascal-кода; её отдельный `compiler-check.exe` не публикуется как NOP.

## Что проверяет сборка

Целостность файлов комплекта; Python x64 и версию; наличие свободного места; хеши wheel-пакетов и согласованность зависимостей; пакеты VC/APO; компилятор и сценарий установщика; регрессионные тесты; архитектуру и фактический запуск FFmpeg, ffprobe, Deno, загрузку API libmpv; извлечение всех четырёх конвертеров; упаковку PyInstaller; состав полученного EXE; функциональные проверки настоящего собранного приложения. После них создаётся установщик и записывается его SHA-256.

Автоматические проверки EXE используют временный профиль и реальные тестовые медиа: воспроизведение, паузу, перемотку, скорость, громкость, примеры категорий конвертации, перекодирование и отмену. Они не заменяют ручную проверку всех кнопок, звука, GPU, устройства APO, установки, обновления и удаления на чистой Windows.

Сетевая загрузка с YouTube проверяется отдельно и не является обязательным условием локальной сборки: доступность сайта зависит от сети, аккаунта и ограничений сервиса. Проверка включённых модулей yt-dlp/EJS/Deno остаётся обязательной. Для дополнительного настоящего сетевого теста перед запуском BAT задайте `set "NOP_TEST_ONLINE=1"`. Без этого в отчёте будет «не проверено».

## После установки на другой компьютер

Передаётся полученный `NOP_Setup.exe`, исходная папка BuildKit не нужна. Локальное воспроизведение и конвертация используют компоненты установщика. Python, Qt, FFmpeg и mpv вручную устанавливать не требуется. Для Visual C++ и Equalizer APO сохраняется отдельное согласие/UAC. В мастере APO нужно выбрать настоящее устройство звука; иногда требуется перезагрузка.

Для проверки установленного приложения есть `CHECK_INSTALLED.bat`. Интерактивные и системные пункты из `docs/WINDOWS_ACCEPTANCE.csv` должны быть выполнены отдельно. Совместимость с Windows 10 1809/17763 и Windows 11 остаётся неподтверждённой до таких испытаний. Windows 10 до 1809 этой веткой Qt 6 не поддерживается; установщик её блокирует. Переход на Qt 5 потребует отдельного порта и не выполнен.

## Если сборка остановилась

Подробности находятся в `logs\last-build.json` и последнем `logs\build-*.log`; копии сохраняются и в рабочей папке. Для распаковки: `logs\extract-libreoffice.log`, `extract-inkscape.log`, `extract-calibre.log`. Для подготовки медиа: `.build-tools\runtime-preparation.log`. Для настоящего собранного EXE: `build\functional-self-test.json` и соседний `.native.log` в рабочей папке.

Старый опубликованный установщик сохраняется до успешного завершения новой сборки. Если запись результата в папку исходников запрещена, файлы остаются в `%LOCALAPPDATA%\NOPBK\R12\release`. Защитное ПО, запрет запуска приложений политикой организации, отказ в UAC и отсутствие необходимого драйвера нельзя заранее устранить изменением сборщика; в отчёте они не объявляются успешными проверками.
