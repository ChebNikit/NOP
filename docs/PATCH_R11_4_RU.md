# NOP BuildKit R11.4 — исправление MSI 1639 с сохранением кэша

Исправление предназначено для текущей папки R11.3, в которой сборка дошла до `libreoffice MSI extraction failed: 1639`.

1. Закройте завершившееся окно сборки.
2. Распакуйте содержимое этого ZIP в ту же папку, где находится запускавшийся `build_windows.bat` и уже установленный `.build-python`. В вашем журнале это папка `NOP_BuildKit_Win10_11_R11` внутри `NOP_Installer_BuildKit_R11_UNVERIFIED (1)`.
3. Рядом с `build_windows.bat` должны появиться `NOP_R11_4_FIX_MSI_KEEP_CACHE.bat` и папка `nop_r11_4_patch`.
4. Запустите `NOP_R11_4_FIX_MSI_KEEP_CACHE.bat`.

Патч сначала проверит свои файлы по SHA-256 и выполнит настоящий тест Windows Installer: распаковку небольшого MSI в путь с пробелами, скобками и кириллицей. Этот MSI содержит один текстовый файл, без CustomAction, записей реестра, служб или ярлыков. Используется `/a`, без обычной установки `/i`. Его исходный WXS включён в архив. Не запускайте тестовый MSI вручную.

После успешного сообщения `R11.4 native MSI self-test passed` патч обновит подготовку конвертеров и автоматически продолжит сборку. Если тест не пройден, исходники не заменяются и сборка не запускается.

Приватный Python, установленные пакеты, подготовленные FFmpeg/Deno/libmpv, скачанный LibreOffice MSI, остальные загрузки и сведения о версиях сохраняются. При повторном запуске сборщик заново проверяет их хеши и использует целые файлы из кэша. Переход в новую распакованную папку вместо применения патча к текущей папке приводит к отдельному кэшу и повторным загрузкам.

## Что исправлено и почему

В R11.3 аргументы передавались в `subprocess.run` списком. Для пути с пробелами Python преобразовывал свойство в `"TARGETDIR=C:\папка с пробелами\unpacked"`. MSI ожидает кавычки вокруг значения: `TARGETDIR="C:\папка с пробелами\unpacked"`. Код 1639 означает ошибку аргументов командной строки. Наличие этой ошибки в формировании команды подтверждено по исходнику; успешное устранение сбоя на вашем ПК должно подтвердиться локальным тестом и повторной распаковкой LibreOffice.

Новый `msi_admin.py` формирует строку с правильным свойством и передаёт её напрямую абсолютному `msiexec.exe` через `CreateProcess`, с `shell=False`. Командная оболочка не участвует. Проверка имени/архитектуры извлечённого движка, проверка хеша скачанного MSI, ограничения версий и приватное размещение файлов сохранены. Режим `/a` применён одинаково к LibreOffice, Inkscape и Calibre. Blender продолжает распаковываться из ZIP.

Существующий `prepare_converters.py` сохраняется как `prepare_converters.py.R11_before_MSI_fix.bak`. Повторное применение допустимо. При ошибке замены уже изменённые файлы восстанавливаются. Неизвестная версия исходника блокирует применение.

Диагностика:

- `logs/patch-r11_4-*.log` — применение патча;
- `logs/patch-r11_4-msi-selftest.log` и `.command.txt` — локальный тест MSI и точная команда;
- `logs/extract-libreoffice.log`, `logs/extract-inkscape.log`, `logs/extract-calibre.log` и соответствующие `.command.txt` — подготовка движков;
- `logs/last-build.json` и `logs/build-*.log` — результат всей сборки.

Если MSI не успеет создать собственный лог, файл `.command.txt` всё равно содержит переданную команду. Ошибки и тайм-ауты не считаются успешной распаковкой; коды 0 и 3010 считаются успешным завершением, после чего проверяются извлечённые файлы.

Официальные основания: [коды ошибок Windows Installer](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes), [синтаксис свойств MSI](https://learn.microsoft.com/en-us/windows/win32/msi/command-line-options), [TARGETDIR](https://learn.microsoft.com/en-us/windows/win32/msi/targetdir).
