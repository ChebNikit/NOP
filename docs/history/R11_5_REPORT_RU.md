# NOP 1.0 — результат подготовки установщика R11.5

29 октября 2026 года.

## Фактический результат

**Подготовлен исправленный BuildKit R11.5. NOP_Setup.exe не создан. Журнал пользователя подтверждает 56 тестов R11.4 на Windows, включая настоящий MSI с кириллицей, и повторное использование медиакомпонентов. Далее сборка остановилась на HTTP 429 метаданных LibreOffice. R11.5 исключает этот запрос и содержит полные локальные пины. Полная сборка, большие движки, установка и LTSC 1809 пока не проверены; главный критерий задания не достигнут.**

Доступная среда — Linux x86_64, Python 3.12. В ней отсутствуют Windows, Wine и Windows-ВМ. PyInstaller не является кросс-компилятором: штатная сборка Windows EXE требует Windows. Поэтому ниже нет утверждений об успешной установке или работе приложения на Windows.

Использованы приложенный `NOP_1.0(20261029-111640).py` и прежний `NOP_Installer_BuildKit_R10B_AUDITED.zip`. Основной код R11 содержит 78 исходных классов; удалённых классов и методов не обнаружено. В нём 13 групп управляемых панелей и 11 категорий конвертации, содержащих 140 пунктов форматов. Собраны реестр кода и 326 подключений сигналов. Подключение сигнала не означает проверку кнопки.

В приложенном файле нет торрент-клиента, RuTracker, WebView2 и самостоятельной универсальной панели интернет-поиска. Это видно по структуре кода и прямо сказано в его встроенной справке. Они не удалялись в этой работе; сборка этого файла не может вернуть функции другой версии NOP.

## Зависимости и компоновка

Среда сборки: отдельный Python 3.13.17 NuGet с проверкой SHA-512, pip 26.2.2, PyInstaller 6.22.3, PyQt6 6.11.0, Qt6 6.11.2 и зафиксированные транзитивные пакеты. `requirements-win64.lock` и `wheelhouse-manifest.json` перечисляют каждую версию и хеш.

Медиакомпоненты: FFmpeg full 9.0.2 + ffprobe, Deno 2.9.8, x86_64 LGPL libmpv из закреплённого официального release asset. Метаданные и хеши получены. Последующие журналы пользователя подтвердили запуск FFmpeg/ffprobe и Deno, а также загрузку libmpv и чтение его версии API на Windows; воспроизведение через плеер пока не проверено. Архив libmpv включён в BuildKit: проверены SHA-256, ZIP, архитектура PE x64 и все 12 требуемых API-экспортов. Он содержит одну libmpv-2.dll и не импортирует одноимённые внешние FFmpeg DLL; это уменьшает риск конфликта с Qt. Позднейший журнал подтверждает загрузку DLL на Windows, но не декодирование или GPU-вывод. Смена версий при повторном запуске не выполняется автоматически.

Приватные движки: LibreOffice 26.2.5.2, Inkscape 1.4.4, calibre 8.16.2; Blender 4.2.23 выбран из официальной ветки 4.2 LTS и закреплён вместе с SHA; в R11.5 включён полный корневой lock всех четырёх двигателей, официальные исходные YAML/контрольные суммы и их происхождение. Нужные DLL остаются в каталогах соответствующего движка, рядом с NOP не подмешиваются. Конвертация этих категорий требует указанных программ: прежнее исключение их из установщика оставляло категории зависимыми от чужого компьютера.

Первоначальные и последующие запросы метаданных LibreOffice/Inkscape сталкивались с 429. В R11.5 полный набор официальных свидетельств получен и включён локально: сетевой запрос метаданных при сборке удалён. Пакеты двигателей и их реальная распаковка на Windows ещё требуют проверки; скачанный LibreOffice MSI сохраняется и проверяется по тому же хешу.

Штатные Qt-hooks PyInstaller должны собрать импортированные Core/Gui/Widgets/Multimedia и их плагины. Неиспользуемые модули Qt не принуждаются к упаковке целиком. Наличие и декодирование ресурсов проверяются перед выпуском; конфликтующие FFmpeg/MinGW DLL в одном процессе блокируются. Полноту реального набора Windows DLL подтверждает только последующий запуск EXE на стенде.

Итоговый сценарий Inno включает все подготовленные файлы, VC Redistributable и Equalizer APO. VC проверяется по подписи Microsoft; Inno — по подписи и издателю Pyrsys; APO — по закреплённому SHA. Установка системных компонентов выполняется через UAC. Для полноценного системного EQ необходим выбор реального устройства и, возможно, перезагрузка; автоматическое обнаружение DLL не заменяет проверку звука.

### Возможность ранних Windows 10

Прежняя ветка R10B содержит адаптер Qt5 и отдельный старый Python/yt-dlp для Windows 7. Её перенос в новый универсальный установщик без проверки не решает задачу: старый yt-dlp не обеспечивает современный EJS, а Qt5 требует адаптации QMediaPlayer/QVideoSink и аудиовыхода. Более новый Python с Qt5 и подходящими mpv/JS-runtime — отдельный возможный путь разработки, но работоспособность и равенство функций для 1507–1803 не доказаны. В R11 не включён ограниченный старый EXE под видом полноценной совместимости. Требование всех ранних Windows 10 остаётся невыполненным.

## Подготовленные проверки самого EXE

`nop_validation.py` вызывается самим `NOP.exe --nop-functional-check <отчёт>`. Он создаёт отдельный профиль, окно NOP и синтетические файлы с кириллицей/пробелами; проверяет 13 открытий/скрытий панелей, продвижение времени mpv, паузу/seek/скорость/громкость, EQ, LUT, смену файла, реальные операции всех 11 категорий на примерах, H.264-перекодирование, ошибку повреждённого входа, отмену запущенного процесса и запись/чтение настроек. Возможности медиакодеков записываются отдельно от конвертации файлов.

Этот тест только подготовлен: в данной работе он не запускался в Windows. Он не прослушивает звук, не оценивает качество картинки, не нажимает каждую кнопку, не настраивает APO и не доказывает все форматы, GPU или перезапуск нового процесса. Патч для текущего R11.4, остановившегося на HTTP 429 при получении метаданных LibreOffice. Исправления PowerShell, BCJ2 и MSI из предыдущих выпусков сохраняются.

1. Распакуйте содержимое этого ZIP в ту же папку, где находится ваш `build_windows.bat` и существующий `.build-python`. По журналу это `NOP_BuildKit_Win10_11_R11` внутри `NOP_Installer_BuildKit_R11_UNVERIFIED (1)`.
2. Запустите `NOP_R11_5_FIX_SOURCES_KEEP_CACHE.bat`.
3. Патч проверит все четыре набора метаданных без сетевых запросов, обновит файлы и автоматически продолжит сборку.

Python, пакеты, FFmpeg/ffprobe, Deno, libmpv, скачанный LibreOffice MSI, другие MSI/ZIP и старый кэш сохраняются. Сборщик повторно использует их после проверки SHA-256. Новые ещё не скачанные пакеты движков по-прежнему требуют интернет.

## Причина повторного запроса

В прежнем полном архиве находился `.build-tools/converter-sources.lock.json` только с Blender и Calibre. При распаковке полного архива поверх рабочей папки этот частичный файл мог заменить локально дополненные сведения. После этого сборщик заново обращался к raw.githubusercontent.com за LibreOffice и получал 429.

R11.5 содержит отдельный полный `converter_sources.lock.json` в корне комплекта. Официальные исходные YAML и файл контрольных сумм Blender включены в `bootstrap/converters`, вместе с происхождением и лицензией манифестов. Сборка проверяет совпадение версий, допустимых хостов, SHA-256 и исходных свидетельств для всех четырёх движков **до начала их подготовки**, без обращения к серверам метаданных. Пины не изменяются автоматически.

Частичный изменяемый файл больше не распространяется в полном ZIP. Уже существующий `.build-tools/converter-sources.lock.json` не удаляется и не используется новым сборщиком. Пакеты `.build-tools/converter-downloads` по-прежнему используются.

| Calibre | 8.16.2 | Windows x64 MSI | 7f052a6027d2331ce214cd4cbf7d8b12125b39a420309745cc6974cf3a000d50 |

Обнаружена и исправлена следующая потенциальная остановка: официальный манифест Inkscape содержит x64 MSI, ARM64 MSI и x64 EXE. Выбирается ровно один MSI архитектуры x64; два x64 MSI по-прежнему считаются ошибкой. Имя ARM64-пакета не используется для определения архитектуры.

Общий загрузчик дополнительно обрабатывает HTTP 429: до трёх попыток, с учётом `Retry-After` в секундах или формате HTTP-даты. Если сервер требует ждать более минуты, сборка останавливается с указанием срока, сохраняя кэш. TLS, проверка хешей и проверка архитектуры сохранены. Это не гарантирует доступность серверов бинарных пакетов; источник текущего сбоя — запрос метаданных — исключён из обычной сборки.

## Применение и диагностика

Перед изменениями проверяются версия исходников и весь полезный набор патча по SHA-256. Создаются резервные копии корневых изменяемых файлов `*.R11_before_SOURCES_fix.bak`; при ошибке уже заменённые файлы восстанавливаются. Повторное применение допускается. Неизвестная версия кода блокирует замену. Патч предназначен для R11.4, с существующим `msi_admin.py`.

После сообщения `R11.5 offline source check passed: all 4 engines` сборка возобновится. Журнал патча — `logs/patch-r11_5-*.log`; журнал сборки — `logs/build-*.log` и `logs/last-build.json`. Для фактической распаковки MSI сохраняются `logs/extract-*.log` и `logs/extract-*.command.txt`.
