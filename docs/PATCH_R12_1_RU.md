# NOP BuildKit R12.1 — проверка Inno до сборки компонентов

Причина остановки в присланном журнале установлена: `prepare_inno.ps1` запускает компилятор до сборки компонентов, но `NOP_installer.iss` безусловно подключал `installer_versions.iss`. Поставляемый файл содержит `#error` до генерации настоящих версий. Это ошибка BuildKit R12, а не Python, кэша или расположения папок пользователя.

Исправлено условное подключение версий: ранний режим получает отдельные проверочные метки, сохраняет отдельный `compiler-check.exe` и компилирует настоящий код мастера. Его `InitializeSetup` всегда возвращает False; запустить установку из проверочного EXE нельзя. Обычный режим по-прежнему включает только настоящий сгенерированный файл версий; защита `#error` не удалена. Итоговый `NOP_Setup.exe` содержит настоящие компоненты.

Кэши в отдельных соседних `NOP_R12_CACHE_Blender`, `NOP_R12_CACHE_LibreOffice`, `NOP_R12_CACHE_Vector_Ebook` теперь импортируются из вложенного `NOP_BuildKit_Win10_11_R12`, даже если там отсутствуют исходники сборщика. Архивы проверяются штатными SHA-256 перед распаковкой. Существующие Python, Inno, wheelhouse и скачанные файлы не удаляются.

Применение: положите **NOP_R12_1_FIX.bat** рядом с **build_windows.bat** уже распакованного R12 и запустите. BAT содержит все новые файлы, проверяет исходную версию и хеши до изменения, сохраняет резервные копии и после исправления возобновляет сборку. Интернет для самого исправления не нужен. Полный основной ZIP также обновлён до R12.1, повторно скачивать его для имеющегося R12 не требуется.

Проверки: исходная ошибка воспроизведена C-препроцессором на Linux; после исправления ранний режим проходит при отсутствующем, блокирующем и старом файле версий, а итоговый режим блокируется при отсутствующем или блокирующем файле. Это **проверено статически**, не компиляция Inno. Запущено 75 регрессий: 70 прошли, 5 пропущены по платформе. Добавлены три проверки реального ISCC для Windows: полная компиляция мастера с блокирующим файлом версий в пути с кириллицей, отклонение блокирующего файла в режиме выпуска, корректная подстановка версий в режиме выпуска. Здесь эти три проверки **не проверены**; они выполнятся при запуске сборщика на Windows после подготовки ISCC. Остальные результаты исходного R12 сохранены в отчёте.

Не заявляется успешная полная сборка или работа установленного приложения на Windows/LTSC. Файлы приложения и версии библиотек в этом обновлении не изменены.

Первичные источники: https://jrsoftware.org/ishelp/topic_ifdef.htm ; https://jrsoftware.org/ishelp/topic_include.htm ; https://jrsoftware.org/ishelp/topic_compilercmdline.htm

Файл обновления дополнительно выполнен на PowerShell 7.4.13 под Linux: обновление и повторный запуск в пути с кириллицей, пробелами, скобками, апострофом, `&` и `$`; проверено сохранение байтов Python/кэша/прежнего выпуска и исходников приложения; изменённые исходники и чужой манифест отклонены до замены; имитация файловой ошибки после нескольких замен восстанавливает все прежние файлы. Это **проверено статически** относительно целевой Windows; запуск BAT и Windows PowerShell 5.1 **не проверен**. Также синтаксис шести PS1 сборщика и встроенного скрипта обновления принят парсером PowerShell 7.4.13 на Linux.
